# REVIEW.md

## Discovered Starter Code Defects

The starter codebase in `app/main.py` was audited against the business rules (R1–R10) and OpenAPI 3.0 contract. A total of 19 defects were identified and fixed:

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `health` (starter line 64) | Does not verify database connectivity; returns `{"status": "ok"}` unconditionally even when MongoDB is down or unreachable. | Stop MongoDB process; `GET /health` continues returning HTTP 200 instead of HTTP 503. | Added `client.admin.command("ping")` inside a try-except block, raising `HTTPException(status_code=503, detail="Database unavailable")` on connection failure. |
| 2 | `compute_late_minutes` (starter lines 30-34) | Grace threshold off-by-one / missed late minutes. Starter computes `minutes = int(total_seconds / 60)` and tests `minutes > 10`. At 10 minutes and 1 second past shift start, `total_seconds` is 601, yielding `minutes = 10`. `10 > 10` is False, returning 0. Per R2, grace is 10:00; any punch strictly > 600s is late. | Punch in at 09:40:01 IST for a 09:30 shift. Starter computes `late_minutes = 0`, expected `10`. | Replaced with strict second check `delta_sec > 600`. When true, returns `int(delta_sec // 60)`, else `0`. |
| 3 | `compute_late_minutes` (starter lines 30-34) | Ignores timezone and overnight shifts. Punch-in can be UTC while shift start is IST. Uses `.replace()` which sets shift start on the punch-in calendar date. For overnight shifts (e.g. 22:00-06:00), an early-morning punch at 01:00 on the next calendar day belongs to the shift starting the previous day, resulting in a negative delta. | Punch in at 01:00:00 IST on July 7 for shift 22:00-06:00 (July 6). Starter returns 0 instead of 180 late minutes. | Resolved shift start against the record's true attendance date in IST, converting all datetimes to timezone-aware UTC/IST instants. |
| 4 | `compute_work_hours` (starter line 37) | Uses Python's built-in `round()`, which employs banker's rounding (round half-to-even) instead of round half-up required by R4 and R8. | Duration of 9630 seconds (2.675 hours). Starter returns `2.67`; required half-up output is `2.68`. | Implemented `round_half_up` helper utilizing `decimal.Decimal` with `ROUND_HALF_UP` quantization. |
| 5 | `compute_overtime` (starter lines 40-43) | Ignores the 30-minute minimum threshold (R3). Grants overtime for any positive elapsed time (e.g., 5 or 15 minutes). | Punch out 15 minutes after shift end. Starter returns `15`, expected `0`. | Enforced `ot_minutes >= 30` condition; returns 0 if under 30 minutes. |
| 6 | `compute_overtime` (starter lines 40-43) | Timezone mismatch and overnight shift boundary. Subtracting offset-aware `end` from naive `punch_out` raises `TypeError`. Also sets `shift_end` on the attendance date even when overnight shift ends on the next calendar day. | Punch out of overnight shift 22:00-06:00 at 06:40 on following day crashes with `TypeError` or miscalculates 24 hours of overtime. | Explicitly added 1 calendar day to `shift_end` when `shift_end <= shift_start`, and ensured both operands are timezone-aware. |
| 7 | Missing helper | Completely missing logic for R5 half-day determination. | No half-day calculation occurred anywhere in the starter. | Implemented `compute_half_day(work_hours: Optional[float]) -> bool`, returning `True` strictly when `work_hours < 4.50`. |
| 8 | `create_employee` (starter lines 69-70) | Check-then-insert race condition on `emp_code`. Two parallel POST requests both pass `find_one` and insert duplicate employee documents. | Run concurrent POST requests with the same `emp_code`; both receive 201 Created and duplicate records exist in the database. | Created unique index on `employees.emp_code` at startup and caught `DuplicateKeyError`, returning HTTP 409 Conflict. |
| 9 | `EmployeeIn` / `create_employee` (starter lines 47-54) | Missing validation for identical shifts and format patterns. Starter accepted `shift_start == shift_end` and invalid formats. | POST employee with `shift_start: "09:00", shift_end: "09:00"`. Starter accepted with 201 instead of returning 422 Unprocessable Entity. | Added Pydantic field validators and regex patterns enforcing `shift_start != shift_end`, valid email regex, and valid `emp_code` pattern. |
| 10 | `create_employee` (starter lines 72-75) | Returns `created_at` as a Python naive datetime object rather than epoch milliseconds integer. | `response.json()["created_at"]` produces an ISO string or object, violating OpenAPI schema expecting an integer epoch milliseconds timestamp. | Standardized `created_at` storage as UTC datetime and serialized as integer milliseconds `datetime_to_epoch_ms(dt)`. |
| 11 | `list_employees` (starter line 83) | Off-by-one pagination bug. `skip = page * page_size`. For `page=1, page_size=20`, `skip = 20`, completely skipping the first 20 employees. | Request `GET /employees?page=1&page_size=20`; returns records 21–40 instead of 1–20. | Corrected formula to `skip = (page - 1) * page_size`. |
| 12 | `list_employees` (starter line 84) | Filter ignored in total count. `total = db.employees.count_documents({})` counts the entire collection regardless of any department filter. | Request `GET /employees?department=Engineering` in a company of 500 employees where 10 are in Engineering; returns `total: 500`. | Updated to `total = db.employees.count_documents(q)` using the filtered query dictionary. |
| 13 | `list_employees` (starter line 85) | Missing deterministic sort order. Does not sort by `emp_code` ascending. | Employees returned in arbitrary natural MongoDB storage order. | Added `.sort("emp_code", ASCENDING)` to the query cursor. |
| 14 | `punch_in` (starter lines 91-92) | Unhandled missing employee returns HTTP 500. `emp = db.employees.find_one(...)` followed by `emp["shift_start"]` raises `TypeError: 'NoneType' object is not subscriptable`. | POST punch-in with unknown `emp_code: "EMP9999"`. Server crashes with 500 Internal Server Error instead of 404. | Added explicit check `if not emp: raise HTTPException(status_code=404, detail="Employee not found")`. |
| 15 | `punch_in` (starter lines 94-96) | Check-then-insert race condition on daily attendance record. Parallel punch-ins for the same date both pass `find_one` and insert duplicate documents. | Send concurrent punch-in requests for the same employee and day; both succeed with 201 Created. | Created compound unique index on `attendance_logs.(emp_code, date)` and caught `DuplicateKeyError`, returning HTTP 409 Conflict. |
| 16 | `punch_in` (starter lines 92-93) | Local system timezone used for date derivation instead of IST, and fails to attribute overnight shifts to the previous day per R1. | Overnight shift worker punches in at 05:00 IST on July 7; assigned calendar date `2026-07-07` instead of `2026-07-06`. | Implemented `attendance_date` helper converting to IST and adjusting date for overnight shifts ending after midnight. |
| 17 | `punch_in` / `list_attendance` (starter lines 108-111, 145-146) | Injects internal MongoDB `_id` as `id` in the API response, violating the OpenAPI `AttendanceRecord` schema. Also returns raw BSON datetimes. | Schema validation failure against `openapi.yaml` which defines no `id` field for attendance records and expects epoch ms. | Removed `id` field and routed all attendance outputs through `format_attendance_record` to serialize timestamps to epoch ms. |
| 18 | `list_attendance` (starter lines 139-142) | Scalability anti-pattern: `docs = list(db.attendance_logs.find(q))` loads entire result set into Python memory, then sorts and paginates in Python. Exhausts RAM on 100k records. | Benchmark on 100,000 records; high memory consumption, high latency, COLLSCAN. | Delegated sorting and pagination directly to MongoDB: `.sort([("date", DESCENDING), ("emp_code", ASCENDING)]).skip(skip).limit(page_size)`, backed by compound index `(date, emp_code)`. |
| 19 | `list_attendance` (starter lines 127-136) | Missing validation for inverted date ranges (`date_from > date_to`). Queries MongoDB with `$gte > $lte` and returns empty list 200 OK. | Request `GET /attendance?date_from=2026-07-10&date_to=2026-07-01`. Returns 200 with 0 items instead of 422 Unprocessable Entity. | Added validation `if date_from > date_to: raise HTTPException(status_code=422, detail="date_from must be <= date_to")`. |

## Non-Defects Examined

1. **One-Based Pagination Parameter Default (`page: int = Query(1, ge=1)`)**:
   - *Observation*: The query parameter `page` defaulted to `1` with minimum `1`.
   - *Analysis*: Verified against OpenAPI specification and Business Rule R10. Page indexing is 1-based throughout the API contract. The starter's parameter declaration was correct; only the `skip` arithmetic (`skip = page * page_size`) was flawed and needed the `(page - 1)` correction.

2. **Collection Naming (`employees` and `attendance_logs`)**:
   - *Observation*: The database client connects to `attendance_db` using collections `employees` and `attendance_logs`.
   - *Analysis*: Verified against `DATA_MODEL.md` and `sample_seed.py`. These names are the exact collection identifiers expected by the evaluation harness and seed data.

3. **Synchronous PyMongo Driver vs Motor**:
   - *Observation*: The starter used synchronous `pymongo.MongoClient` in FastAPI route functions.
   - *Analysis*: FastAPI runs synchronous route functions in an internal AnyIO threadpool worker per request, preventing event loop blocking. PyMongo is thread-safe, manages connection pooling out of the box, and provides direct support for MongoDB 6.0 wire commands (`explain` with `executionStats`, `$densify`, `$setWindowFields`). Retaining PyMongo avoids async driver overhead and aligns with the existing architecture.
